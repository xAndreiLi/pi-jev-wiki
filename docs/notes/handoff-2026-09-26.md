## 3. What shipped this session

**Policy** — Jev verdicts are advisory: the agent has the final say and records overrides via
`wiki_finalize` (`overrides`); sensitive/injection content and silent contradiction resolution stay
hard boundaries. Bulk review resolve and user-stated auto-accept keep upkeep agent-owned.

**Semantic search (0.5.0)** — PGlite + pgvector at the user level; chunking per active claim + page
section (generated files excluded); presets `performance` (EmbeddingGemma-300M) and `quality`
(Qwen3-0.6B); model chosen before the first build; hybrid BM25+vector via granularity-aware RRF with
wiki-tagged results; `wiki_index` (`status`/`model`/`discover`/`rebuild`/`add`/`remove`/`enable`/
`disable`); discovery across home + WSL; cold-index fallback to keyword; queries never download.

**Catalog (0.6.0)** — `wiki_toc scope=all` reads per-wiki TOC manifests (`.jev-wiki/toc.json`,
gitignored, single-writer) plus index state and reports pages, topics, chunks, model, last indexed,
and staleness flags (`toc-stale`, `index-stale`, `root-missing`, `never-indexed`, `model-mismatch`);
`wiki_toc wiki=<name>` for one wiki; paged, failure-isolated (100 wikis ≈ 28 ms);
`npm run toc:refresh` migrates pre-manifest wikis.

**Jev retrieval judgments (0.6.0)** — one batched call per query: relevance per candidate (rerank)
plus evidence sufficiency; `search.jev.rerank` = `auto` (hybrid only) | `always` | `never`;

same query scored 0.02 against the life wiki vs 0.97 against the cultivation wiki.

## 4. Immediate open work — cross-wiki write routing

**Problem observed:** a capture from a session run in `~` (life wiki) produced claims about
`pi-jev-wiki` (one-source install, cadence semantics, legacy alias). Writes are local-only by design,
so they were dropped: the repo wiki could not receive them. Consultation crosses wikis; writes do not.

**Design agreed in principle (needs the two decisions below):**

- **Registry → routing map.** Add optional `projectRoot` to registry entries (`resolveWikiRoot`
  already walks from a project path and can record it); derive it for discovered/legacy entries.
- **Route by evidence.** Insights carry evidence paths; match them against registered project roots
  (longest prefix wins) and group claims per target wiki. A session touching two projects yields
  claims for two wikis.
- **Adjudicate per wiki.** Placement/`already_known`/candidates are per-wiki, so run the pipeline once
  per target using that wiki's layout and page set (no candidate cross-pollination).
- **Guardrails.** Targets must be registered and `enabled`; no arbitrary paths; routing logged as
  `capture.route` (claim → wiki, matched prefix); captures report every wiki they wrote to; an
  explicit `wiki: "<name>"` always wins, and an unregistered name errors instead of falling back.
- **Config.** `capture.routing: "local" | "auto"` (default `local`); set Andrei's to `auto`.

**Phases**

1. **Explicit targeting (small, safe).** `wiki_insights`, `wiki_ingest`, and `wiki_finalize` accept
   `wiki: "<name>"`. Auto-capture computes a *suggested* target from touched paths and includes it in
   the pending-capture note (the agent applies it). Fixes today's case without changing write
   semantics.
2. **Auto-routing (the real feature).** Per-claim routing by evidence prefix + per-wiki adjudication;
   one capture updates several wikis; `capture.routing`; `capture.route` ledger entries; catalog shows
   each wiki's project root.

**Decisions to confirm with Andrei before implementing:**

1. Do Phase 1 only, then Phase 2 — or both in one pass? (Phase 2 roughly doubles the work and touches
   the capture pipeline's core.)
2. Split granularity: per-claim routing so one capture updates multiple wikis (recommended), or one
   target per capture with the dominant root winning (ties → session's local wiki)?

## 6. Gotchas worth carrying forward

- **One install source only** for `pi-jev-wiki` (npm *or* local folder *or* git). Two copies =
  `Tool "wiki_*" conflicts with …` at startup and the extension refuses to load. `pi list` /
  `pi remove <source>`.
- **Extensions load at session start** — config or plugin changes need `/reload` or a new session.
- **Capture routes by the session's working directory** (this is what §4 fixes).
- **Capture gating:** ≥ 0.6 Jev `worth_capturing` pre-screen, 10-minute debounce, ≥ 3 messages, and
  proposals only — the agent writes and finalizes.
- **Generated files are never indexed** (`index.md`, `log.md`, `toc.md`, `toc/`); the TOC manifest is
  derived and gitignored; `npm run toc:refresh` regenerates TOC + manifest.
- **Windows specifics:** `execFileSync("npm")` needs `npm.cmd` + `shell` (see `scripts/release.ts`);
  Git Bash cannot create UNC paths (pipe through `wsl.exe -- bash -c 'cat > …'`); Node's `/tmp` is
  `C:\tmp` while `gh` reads Git Bash's temp — pass an explicit Windows path.
- **Tests:** `npm run test:all` (typecheck + unit + scale + vector). Vector tests need the PGlite
  devDependencies; live E2E needs the cached models.
