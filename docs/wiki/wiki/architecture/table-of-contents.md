# Table of contents hierarchy

**Responsibility.** The wiki maintains two coordinated table-of-contents files so agents get a compact, fast-to-read view while the system keeps a complete machine catalog.

**Public surface.**
- `index.md` — complete machine catalog of all wiki pages.
- `toc.md` — compact agent-facing view with per-topic tables.
- `toc/*.md` — per-topic tables referenced by `toc.md`.

**Dependencies.** Generated by `wiki_finalize` and `wiki_lint`; consumed by agent prompts and `wiki_toc`.

**Key files.** `docs/wiki/wiki/index.md`, `docs/wiki/wiki/toc.md`, `docs/wiki/wiki/toc/`

## Invariants

- `index.md` always contains the complete catalog; `toc.md` is a strict subset/view.
- At ~1,000 pages the agent-facing `toc.md` remains ~1 KB.

## Change impact

- Adding a large number of pages does not bloat the agent-facing TOC because per-topic tables live under `toc/`.
- If you change TOC generation logic, update both `index.md` and `toc.md` (and `toc/`).
